# Colab Comfy Studio 创作 API 改造文档

交给 Codex 在 `Naoya666/colab-comfy-studio` 当前分支实现。参考基线为 `6c14e36`，动手前以当前分支的实际实现为准。

## 1. 使用目标

管理员在原生 ComfyUI 调通工作流并导出 API JSON，按 Studio 现有流程完成真机冒烟、验收和发布。随后在「创作 → API 设置」授权工作流版本并保存运行配置。酒馆配置一次兼容地址和 Key，之后可以在酒馆随时切换整份已授权的 API JSON，下一次出图自动使用对应版本。

管理员也可以在酒馆发图前点「启动工作流」，由 Studio 提前选择或启动实例、准备依赖并预热模型。首个正式请求应当能复用已准备好的实例和模型。

## 2. 接入地址和执行链路

| 入口 | 地址示例 | 执行链路 |
| --- | --- | --- |
| 原生 ComfyUI | `https://comfy.example.com` | 用于编辑、试跑和导出，沿用现有原生入口 |
| 创作 API | `https://comfy-api.example.com` | VPS 上的 ComfyUI 兼容接口，调用 Studio 的任务准入、调度器和创作 Worker |

两个域名可指向同一 VPS 和同一后端，按 Host 路由。创作 API 由 VPS 接收 job，Colab 端由创作 Worker 调用 VM 内的 ComfyUI loopback。原生会话关闭时，创作 API 的预热和生成仍须独立工作。

核对项目现有酒馆接入方式及目标版本的请求和响应。至少支持 `POST /prompt`、`GET /history/{prompt_id}` 和 `GET /view`，以及实际客户端用到的探测、节点及模型信息接口。探测和元数据查询从 VPS 的配置及获准工作流快照取数。酒馆现有客户端若不会为所有请求带鉴权头，沿用项目的本机或私网中继注入专用 Key。

- `/prompt` 接收标准的 `{"prompt": {...}}`，入队后立即返回客户端所需的 `prompt_id`。开机、预热与生成在后台处理。
- 持久化 `prompt_id` 和 Studio job 的映射。History 按酒馆需要的状态和输出结构返回，保留正确的输出节点归属；View 只提供该 Key 有权读取且已登记的产物。
- 沿用鉴权、限流、并发上限和任务所有权约束。若客户端提供幂等键，沿用现有重试语义；两次主动发起的相同工作流与参数可以产生独立任务。

## 3. 完整工作流匹配

1. 每把创作 API Key 可勾选多份工作流的**具体发布版本**。只使用同一 owner、已经真实冒烟验收并仍可执行的记录。新版本不会自动替换已授权版本。管理员可以撤销某个版本的 API 授权；创作页“默认版本”的 `active` 标记沿用其原有语义。
2. 解析酒馆提交的完整 API 图。比较节点 ID、节点类型、连线与固定输入，JSON 键顺序及明确识别为纯展示的元数据可忽略。通过发布版本的 `manifest` 参数绑定，只从明确开放的位置提取可变值，例如正负提示词、seed、尺寸，并复用现有类型、范围及参数校验。模型文件名、LoRA 和其他固定输入仍参与匹配。
3. 唯一匹配后，拿**已发布快照 + 提取出的参数**走 Studio 准入和绑定。素材等特殊字段按现有 Studio 机制转译。有客户端暂未支持的字段时返回可定位的错误。
4. 零个匹配或多个匹配均拒绝，并在管理员的检查结果中显示原因和涉及的版本。两个版本若只在可变字段的默认值上不同，管理员可调整该 Key 的授权名单以消除歧义。

## 4. 创作 → API 设置

界面参考「原生 ComfyUI → API 管理」，由管理员管理。

| 设置 | 行为 |
| --- | --- |
| 接入地址 | 显示可复制的创作 API 地址。 |
| 专用 Key | 支持创建、配置获准版本和撤销。一把 Key 可用多份发布版本。只在创建时呈现明文。 |
| 默认 Colab 账号与 GPU | 使用创作页现有的授权账号和 GPU 规格选择。已配置的 GPU 是新分配实例时的显式规格，优先于工作流默认规格。 |
| 实例启用方式 | 复用创作界面现有四档名称、枚举、策略和后端校验。 |
| 自动启动 | 开启后，通过鉴权、匹配和任务准入的 `/prompt` 可以按需开机。关闭后，`/prompt` 使用可复用实例；若没有，提示先到 API 设置手动启动。管理员的「启动工作流」仍可主动开机。 |
| 保存 | 全局运行配置通过后端保存，刷新页面或重启服务后恢复。手动启动与 API 提交使用最近一次成功保存的配置，界面有未保存修改时提示先保存。保存失败保留旧配置并显示错误。 |

四档策略沿用创作页的行为，API 和手动启动都走同一套实例调度与回收逻辑。

| 策略 | 现有界面语义 |
| --- | --- |
| 节省 `save` | 任务结束后释放 |
| 批次 `batch` | 兼容任务复用 |
| 智能 `smart` | 短暂空闲保留，可配置**空闲保留时间**和**单个任务最长运行时间**，沿用已有保活策略 |
| 保留 `retain` | 继续使用此机器，沿用创作页现有参数与限制 |

空闲时间和单任务运行上限使用现有时间单位、默认值和服务端限制。空闲保留、单任务超时和实例硬截止分别计算。手动预热结束后的实例回收仍听从当前策略，界面显示可用状态和实际截止。需要在发图前留出等待窗口时，可选智能策略。

### GPU 选择规则

保持创作模式现有的显式 GPU 覆盖能力。**工作流默认 A100，API 默认 L4，规格不同本身可正常提交和尝试分配 L4**。保留现有兼容性提示、预算控制和真实错误，例如账号当前无法分配 L4、租约不可复用，或执行时实际发生 OOM。已有可复用实例按创作模式规则选择，实例上的实际 GPU 同样允许不同于工作流默认值。

## 5. 检查匹配与手动启动

| 操作 | 输入与结果 | GPU 行为 |
| --- | --- | --- |
| 检查工作流匹配 | 粘贴或上传酒馆使用的完整 API JSON，可按所选 Key 的权限检查。返回命中的版本、可变字段、歧义或具体差异。 | 只检查，不入队、不申请 GPU。 |
| 启动工作流 | 选择已发布版本，或检查命中后直接启动。以异步任务返回启动和预热进度。 | 有可复用的活动实例时在该实例准备；没有时按已保存的账号、GPU 和策略分配。 |

手动启动流程：

1. 校验发布版本与依赖快照，读取已保存的配置。通过创作调度器查询当前可复用的活动或正在启动的实例。已有实例繁忙时按现有排队和租约规则协调，避免打断生成或重复申请。
2. 在目标 Colab 实例准备 ComfyUI 和锁定的节点依赖，复用创作模式现有的模型解析、下载及缓存路径。已存在且验证有效的权重直接复用。记录发布版本、环境及模型指纹、实例 ID、进程身份和执行设备。
3. 下载完成后实际预热目标模型。UI 分别显示「准备实例」「准备依赖」「下载模型」「加载模型」「就绪」和失败原因。若当前只能完成磁盘缓存或服务启动，明确显示实际阶段。实现显存预热时，使用工作流对应的受控预热操作；必要时执行有界的内部预热图，不生成酒馆可见的任务或作品。
4. 保证后续正式创作 job 能复用预热所用的 ComfyUI 进程和模型缓存。若现有创作路径每个 job 启动独立进程，需要接通可复用服务与正式生成，验证相同实例 ID 和进程身份。进程重启、租约释放或版本／依赖变更时使就绪状态失效。模型是否仍驻留以运行时实际状态为准。
5. 按实例和预热指纹合并重复点击。预热与正式请求并发时，共享同一准备任务或按现有队列串行。两个工作流的模型可分别准备，但显存是否能同时驻留取决于 ComfyUI 的实际缓存和 GPU 容量。失败显示阶段及原因，并沿用现有预算、清理和重试机制。

## 6. 代码入口与验收

优先复用当前实现。以下为参考基线中的入口。

| 现有代码 | 可复用部分 |
| --- | --- |
| `web/src/components/RuntimeSelection.tsx` 与创作页提交逻辑 | GPU、账号和四档策略交互 |
| `api/app/native_api.py`、`api/app/native_proxy.py` | Key 与协议兼容思路、模板匹配和酒馆访问范围 |
| `api/app/admission.py`、`api/app/gpu/manifest.py`、`api/app/gpu/specs.py` | 已发布版本准入、参数绑定和 GPU 覆盖 |
| `api/app/gpu/instances.py`、`scheduler.py`、`runtime_worker.py` | 实例复用、租约、依赖缓存和 ComfyUI 执行进程 |

交付前验证：

- 同一把 Key 依次提交两份完整的已授权 JSON，分别命中正确版本并取到图；提示词与 seed 可变，修改固定字段、未发布或未授权版本、歧义匹配均在开机前拒绝。
- 配置保存后刷新页面和重启后端，读取结果一致。四档请求走与创作界面一致的策略。智能模式的空闲保留和单任务运行上限分别生效。
- 默认 GPU 与工作流默认规格不同，验证以 API 设置指定的规格入队和分配；已有兼容实例可以复用。同测自动开机关闭时的手动启动路径。
- 无实例时手动启动并完成预热；已有实例时复用并完成预热。重复点击或并发提交不重复开机；冷启动故障、预热失败、租约释放均有可见状态和正常恢复路径。
- 关闭原生会话、停用原生反代后，用酒馆实际验证探测、生成、轮询与取图。对比同一工作流的冷启动和预热完成后的首图耗时，并通过实例和进程记录确认复用。离线测试和真机验收结果分别记录。
