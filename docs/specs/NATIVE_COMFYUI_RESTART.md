# 原生 ComfyUI 重启与模型库下载恢复设计

## 目标

在 Studio 的「原生 ComfyUI」页面，把「重启原生 ComfyUI」放在「进入原生 ComfyUI」旁边。重启当前 Colab 实例上的 ComfyUI 进程，保留 GPU 实例、租约、会话截止时间以及 Drive 工作流和输出。重启前同步统一模型库中已就绪的模型索引，让用户入库后能在同一台 GPU 上切换模型。

Manager 的进程重启已经在 bero 的同一台 L4 上验证。当前统一模型库的快捷方式由原生会话初始化流程生成，单独调用 Manager 重启只会重新加载 ComfyUI。新按钮把索引同步、重启和恢复检查串成一次操作。[现有原生会话与模型索引](../NATIVE_COMFYUI.md#drive-目录与持久化)

## 页面行为

| 状态 | 显示与操作 |
| --- | --- |
| 原生服务就绪 | 左侧为主按钮「进入原生 ComfyUI」，右侧为次按钮「重启原生 ComfyUI」。窄屏允许自动换行，阅读和键盘顺序保持一致。 |
| 点击重启 | 弹出确认对话框。「将重启当前 GPU 实例上的 ComfyUI，并同步已就绪的模型。页面会短暂断开，请先保存工作流。」提供「取消」和「重启」。 |
| 重启进行中 | 保留按钮区域。两按钮禁用，重启按钮显示「正在重启…」。状态依次显示「同步模型索引」「重启 ComfyUI」「等待服务恢复」。刷新页面后继续显示同一个操作的进度。 |
| 生成、Manager 安装或 Drive 写入仍在进行 | 显示后端返回的阻塞原因和「请等当前操作完成后重试」。 |
| 重启成功 | 显示「ComfyUI 已重启，模型列表已刷新」，恢复两个按钮。已打开的原生标签页可刷新后继续使用。 |
| 重启失败或超时 | 显示失败阶段和错误原因。实例仍存在时保留当前实例的状态和已有停止入口。只有后端确认可以再次重启时才启用重试。 |
| 无活动原生实例 | 沿用现有启动或复用界面。 |

前端主要改动在 `web/src/pages/NativeComfyPage.tsx`，复用现有按钮样式、API 错误处理和三秒状态轮询。状态消息通过 `role="status"` 宣告，失败使用现有 `role="alert"`。重启期间反代可能暂时返回 502，页面应根据重启操作的状态继续等待，避免因单次 `ready=false` 切换到申请 GPU 表单。

## API 与重启流程

新增认证接口 `POST /api/gpu/native/restart`。请求体带当前 `instance_id`，请求头带 `Idempotency-Key`。受理后返回 HTTP 202 和 `restart_id`。复用 `GET /api/gpu/native/status` 返回最近一次操作的阶段、实例 ID 和可展示错误。操作状态独立于原启动任务状态，并按租约保存，前端刷新后仍可查询。

1. **检查会话并保留重启资格。** 服务端核对当前用户、原生实例和租约，确认会话就绪且未进入停止、排空或到期流程。同一租约同时只受理一次重启，同一幂等键返回已有操作。建立重启状态后，暂停两个提交入口的新生成和安装请求，等待已受理的写请求结束，再检查共享执行队列、Manager 队列及 `/studio_native/state` 的同步状态。有任务或同步未完成时撤销重启状态并返回明确的忙碌原因。插件归档已写入且仅等待重启激活时，可以继续。调度锁只用于状态转换和租约复核，外部请求在锁外执行。
2. **同步模型库索引。** 复用 `api/app/gpu/native_runtime.py` 的索引规则，为当前 Drive 账号下 `ready` 的模型补建 `models/native-index/<类别>/` 的快捷方式，沿用文件 ID 前缀。已存在且目标一致的快捷方式直接复用，原有权重和原生模型目录保留。通过运行时挂载刷新对应目录，并验证新增快捷方式可见。索引失败时返回具体原因，保留仍在服务的 ComfyUI。
3. **重启当前 ComfyUI 进程。** 再次核对租约及空闲状态。Studio 后端通过既有认证隧道向 Manager 的 `POST /v2/manager/reboot` 发送一次请求。ComfyUI 重启会清除进程内模型缓存，下一次出图可能重新载入权重。若重启调用得到 502 或连接断开，进入恢复检查，避免重复发送重启请求。
4. **验证同一实例恢复。** 在 `/studio_native/state` 暴露进程启动时生成的标识。成功须同时满足同一租约仍有效、启动标识已变化、`/system_stats` 可用、新增模型出现在对应加载器的文件列表。旧进程仍能响应健康检查时继续等待。若实例被回收、启动超时或模型未出现在列表中，分别记录结果并解除提交限制；遇到重启结果不明时先复核状态，再决定是否允许重试。

后端入口位于 `api/app/native_routes.py`。在 `api/app/gpu/native.py` 复用会话身份和写入准入检查，在 `api/app/gpu/native_runtime.py` 复用模型索引路径与命名规则。整个流程使用现有实例和隧道，继续遵循该租约的到期及回收策略。

## 模型库大文件传输恢复

2026-11-18 19:47（北京时间），bero 模型库准备 `diffusion_models/krea2_turbo_int8_convrot.safetensors`（13,492,686,496 字节）时，`model-worker` 触发 384 MiB 容器内存限制并退出。容器自动重启后，同一任务的 `attempt` 增至 2。现有 `Transfer.run()` 会在恢复时删除旧的 `transfer-*` 目录，随后从头下载。检查时第二次已完成下载和校验，正在上传。现场只有一条模型记录和一条准备任务，Drive 当时没有已完成对象。第一次下载的实际完成字节数未保留。

修复入口在 `api/app/gpu/model_library.py`，复用 `model_sources.py` 的来源解析和当前任务模型。模型库下载继续由独立进程执行。ComfyUI 的重启只索引已经就绪的模型，模型库仍在准备的文件可在完成后通过下一次索引同步加入。

1. **限制内存占用。** 下载、散列和上传使用有界缓冲。Drive 分块上传以小块迭代读取文件，并设置准确的 `Content-Length` 和 `Content-Range`。用容器的实际内存指标确认大文件可在现有 384 MiB 限制内完成。
2. **保留下载检查点。** 暂存目录按任务标识定位，记录已固定的来源版本、预期长度和 SHA-256。Worker 被终止后，校验本地已写入的数据，再从有效偏移请求 HTTP Range。仅在来源身份可确认、返回 HTTP 206 且 `Content-Range` 匹配时追加。来源变化、服务器返回全量内容或范围异常时重新开始，并显示原因。完整暂存文件通过全量校验后可直接进入上传。清理只处理已完成、已取消或确认过期且无活动进程持有的任务目录。
3. **恢复 Drive 上传。** 复用任务中加密保存的可恢复会话，先查询 Drive 已确认偏移，再从该位置继续写入。会话失效时，先按内容哈希查询并验证是否已有完整对象，再用已校验的本地文件开启新会话。最终分块响应丢失时执行同样的核对。远端大小与校验值通过后才提交 `ready` 并清理暂存。本地任务重试维持原模型和任务标识，上传会话地址留在后端。
4. **显示当前传输阶段。** 模型库分别显示「下载中」「校验中」「上传至 Drive」。自动恢复时显示尝试次数、当前阶段和有效续传偏移。若必须从头下载，明确显示原因，让用户能区分下载重跑和上传进度从 0 开始。

## 验收

- **页面。** 就绪状态下两个按钮相邻。取消确认时无重启请求。连续点击、双标签页提交和刷新页面均只对应一次重启。暂时返回 502 时，页面持续显示重启进度，恢复后可用「进入原生 ComfyUI」再次打开。
- **空闲与权限。** 正在生成、排队、安装插件、同步 Drive 或停止时，请求返回对应原因。其他用户的实例与已过期租约无法通过此入口操作。Manager 重启请求只发送一次。
- **实例保留。** 在真实 L4 上比较重启前后的 Colab 运行时、实例 ID、租约 ID 和截止时间。上述标识一致，ComfyUI 启动标识变化，Drive 中既有工作流与输出可读。
- **模型可用。** 在 L4 在线时，将 Krea 2 Turbo INT8 底模和 Qwen3VL 文本编码器入库。两项就绪后使用新按钮，验证加载器能选中两项，已有 Qwen Image VAE 可复用。提交一张小图，确认模型可以实际读取并完成推理。
- **故障恢复。** 模拟索引失败、重启连接断开、旧进程仍健康、启动超时和 Colab 回收。检查页面显示正确阶段，后台按同一实例核对结果。
- **下载恢复。** 分别在下载期间、下载完成后及上传期间终止 Worker。恢复后核对 HTTP Range 或 Drive 确认偏移，确认完整暂存文件可直接用于上传，原任务继续推进。覆盖来源忽略 Range、来源版本变化和 Drive 会话过期，核对回退路径。
- **内存与去重。** 在 384 MiB 容器限制下完成 13.49 GB Krea 2 权重的下载、校验和上传，记录峰值内存和 Worker 重启次数。模拟最终上传响应丢失，验证最终只有一份有效 Drive 对象、一条模型记录和一条准备任务。

## 发布和回退

先用模拟会话和传输中断覆盖 API、轮询、并发与故障分支，再在同一台真实 L4 完成模型入库和出图验收。需要回退时，先安全暂停正在传输的任务并保留检查点，再恢复原页面和后端版本。已有有效 Drive 对象与快捷方式可继续用于现有加载流程。
